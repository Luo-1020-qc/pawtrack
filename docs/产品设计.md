# 宠伴时光：产品与交互设计

## 目标

依据「养宠成长记录与社区_方案设计.md」制作可部署的交互雏形，优先展示完整的产品结构及核心操作闭环。

目标用户：需要持续记录宠物成长、整理健康档案、寻找同城交流伙伴的年轻宠物家长。

主线：选择宠物 → 添加健康记录/发布日常 → 在健康图表与成长时间线回看 → 通过地域筛选发现宠友。

## 信息架构与视觉

五个导航项：`首页 / 记录 / 时间线 / 宠友 / 我的`。移动端使用固定底部导航，内容在 520px 宽以内；桌面使用侧边导航与双列动态卡片，充分利用空间。

视觉使用奶油白背景、深墨绿色主色、鼠尾草绿辅助色，以及暖杏色提示。以宠物插画、留白、圆角卡片与短句体现陪伴感。演示插画为 CSS 与 emoji，无外部图片服务依赖；自行发布可附照片。

交互按钮提供可见焦点；图标按钮有无障碍名称；弹窗支持 Esc 关闭与焦点约束，关闭后恢复原焦点；移动布局兼顾底部安全区；减少动态偏好关闭过渡。

## 核心操作闭环

| 用户行为 | 反馈 | 持久化与联动 |
| --- | --- | --- |
| 新增宠物 | 创建成功提示，自动切换至新宠物 | 新档案进入所有宠物切换器 |
| 添加体重 | 成功提示 | 曲线、记录列表及时间线同步更新 |
| 记录疫苗/驱虫 | 校验日期顺序，显示计划日期 | 剩余天数每日重算，进入健康计划及时间线 |
| 发布宠物日常 | 成功提示，动态置顶 | 与当前宠物关联，进入该宠物时间线 |
| 点赞/取消点赞 | 图标与数量立即变化 | 刷新保留，避免重复点赞叠加 |
| 筛选同城/城市/地区/物种 | 立即更新结果，空结果提供提示 | 距离仅模拟，明确展示 |
| 更新个人资料 | 成功提示 | 后续发布使用新昵称与地域 |
| 删除记录/重置 | 操作前确认 | 删除后更新相关图表及时间线；重置恢复种子数据 |
| 导出数据 | 下载 JSON，成功提示 | 为本地浏览器记录提供备份副本 |

## 数据设计

`Pet`：id、name、species、breed、gender、birthday、avatar。

`HealthRecord`：id、petId、type（weight/vaccine/deworm/other）、label、value、date、nextDate、note。将方案中的 `dewarm` 拼写统一为 `deworm`；nextDate 是显式计划日期。

`Post`：id、authorId、author、avatar、petId、content、title、image、likes、liked、city、district、createdAt；演示图额外包含 scene 与 animal。

`User`：id、nickname、city、district、avatar。

`Friend`：id、nickname、city、district、avatar、pet、bio、distance、followed。

状态通过 React Context 共享，在修改时写入 localStorage；版本化 key `pawtrack:v1`，首次进入初始化演示数据，异常存储提示用户导出。

## 本版范围

完成全部五个页面的本地交互；在线网站是产品雏形，社区社交、地域距离、用户身份为演示，不承诺真实多用户数据或消息推送。

后续可在保持同一公开域名的前提下接入后端、照片存储、真实定位授权与站内消息。这些不影响本版评审与产品体验。
